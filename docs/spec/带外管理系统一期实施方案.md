# 带外管理系统一期实施方案

- 状态：方案已实施；应用、Compose、开发/测试库与扩展、基础业务表和初始管理员均已建立。浏览器、设备只读及人工电源验收按部署环境分别记录，未执行的不记为通过。
- 来源：带外管理系统一期需求说明，本仓库为开源整理版。
- 本期：HP iLO4、Dell iDRAC 8，服务器管理、静态硬件、实时与历史监控、手动电源操作。
- 约束：完整复用指定 Ant Design Pro 模板的界面；后端 .NET 10、EF Core、PostgreSQL 和时序扩展；新增业务代码配中文注释。

## 1. 已确认事实与实施边界

1. 当前已建立后端四层工程、独立 PC 应用、接口合同与检查入口；历史来源资料不作为本期执行入口。
2. 指定模板实际使用 Umi Max，包含登录、原首页、头像、语言和主题设置。模板的 SettingDrawer 在开发和生产均存在，应原样保留。
3. 开发环境要求 .NET SDK 10.0.300、Node.js >= 22（PC 工程要求）；服务端 PostgreSQL 17 + TimescaleDB 2.31 独立实例建议使用专用端口（示例为 55432），不复用其他项目的容器、数据库或数据卷。
4. 开发测试设备自行准备。设备地址、账号和密码只放本地私有配置，不进入共享设计文档、示例、前端或日志；示例地址使用 RFC 5737 文档网段。
5. 本期包含手动开关机与重启能力，但真实电源动作默认关闭（`PowerControl.Enabled=false`），由使用者在明确确认目标服务器、动作与时机后启用。任何自动化或 AI 助手不得以联调、验收为由执行真机电源动作。
6. 初始 Docker Hub/VM 代理路径超时已通过可信替代路线解决：宿主获取官方 ECR PostgreSQL 17.11 ARM64 OCI，逐层 SHA-256 校验后导入 Podman，再离线安装官方 TimescaleDB 2.31.0 软件包。实际容器健康、两个数据库、扩展与账号隔离均已核验；固定来源见 deploy/oob/package-manifest.json，未调整全局或 Podman 代理。

本次已读取 HP ProLiant DL360p Gen8 / iLO4 2.82 和 Dell PowerEdge R630 / iDRAC 8 2.85.85.85 的库存与指标：HP 返回 CPU、内存、P420i/磁盘、后备电源、42 个温度项和 8 组风扇百分比；Dell 返回 CPU、内存、控制器/8 块磁盘、4 个温度项和 14 路风扇 RPM。缺失字段按能力显示，短时联调不等于所有负载与固件的稳定性验收。未发送电源、固件或配置动作。

## 3. 后端结构与统一驱动

采用 Domain、Application、Infrastructure、Api 四层。实体分类放 Models，接口放 Service，实现放 Service/impl，公共能力单独分类；以已确认目录规范为准，新增实现提供中文说明。

| 层 | 主要内容 |
| --- | --- |
| Domain | 用户、服务器、硬件快照、指标系列、采样和电源操作模型 |
| Application | 统一 ApiResult、DTO、服务接口、能力与业务错误 |
| Infrastructure | EF/Npgsql、发号、凭据保护、两类驱动、采集调度和设置持久化 |
| Api | Controller、身份会话、权限、请求验证、OpenAPI 与依赖组装 |

统一接口拟为 `IOutOfBandService`，分别实现 `Ilo4Service`、`Idrac8Service`，按服务器控制器类型解析驱动：

| 方法 | 职责 |
| --- | --- |
| `TestConnectionAsync` | 验证访问，读取控制器类型/固件、型号和可用能力；测试不自动保存服务器 |
| `GetCapabilitiesAsync` | 发现协议、库存、传感器和电源动作能力，不发送写请求探测 |
| `ReadInventoryAsync` | 读取静态硬件树，保留控制器和下挂磁盘关系 |
| `ReadTelemetryAsync` | 返回实时数值、单位、时间、质量与来源 |
| `ExecutePowerActionAsync` | 仅映射明确支持的主机电源动作，非任意 URL/JSON 转发 |

优先按真实资源链接发现 Redfish/OEM 资源，不把示例资源 ID 写成所有设备的规则。同源绝对链接与相对链接均规范化，拒绝将凭据发送到其他主机。iLO4 按实际能力兼容旧资源结构；需要时在驱动内部增加 RIBCL/XML 读取，未来控制器版本新增驱动。

统一 HTTP 返回 ApiResult 并保留真实状态码；文件等协议按实际类型。普通实体通过 IIdService 复用已锁定的发号组件，EF 明确禁止数据库自增，部署实例的 WorkerId 必须唯一；未假设外部集中发号服务已存在。long 在 JSON 中传字符串，数据库存 UTC，展示时转换到 Asia/Shanghai 一次。

## 4. 服务器管理与采集

新增/编辑包含名称、品牌、控制器类型、管理地址、账号、密码、采样间隔秒数、启用状态和设备证书信任设置。HP 本期只能选择 iLO4，Dell 只能选择 iDRAC 8；类型和固件版本分开，固件由连接读取。

- “连接测试”返回访问、认证、型号、控制器固件及能力状态；服务端核验选择的品牌/控制器是否匹配，不因缺少操作系统主机名而判定连接失败。
- 首次保存后可读取库存；“刷新服务器信息”单独刷新 CPU、内存、电池、电源设备、控制器和磁盘快照。逐部分记录成功/不支持/暂不可用，失败不抹掉上一份成功快照。
- 管理主机名、服务器名称和 OS 主机名分字段；OS 信息只有设备确实提供时才显示。
- 采样默认建议 30 秒，允许输入 1–86400 的整数；显示配置间隔和实际采集时间。一个周期超时不重叠启动同服务器第二轮，全局限并发、超时和失败退避。
- 认证失败停止高频重试，避免锁号；一台服务器或一个传感器失败不阻断其他服务器/可读指标。

| 指标 | 数据与展示规则 |
| --- | --- |
| 电源 | 当前 W、设备报告的可用容量与利用率、各 PSU 读数、设备统计窗口内平均/最小/最大 |
| BTU/h | 可从 W 换算并标记换算来源；容量百分比只在分母语义明确时计算 |
| 累计能耗 | 优先设备原生 kWh；没有时可按真实采样积分估算，明确起点、缺口和估算标识，不跨离线缺口冒充连续实测 |
| 峰值 | 设备窗口峰值、设备历史峰值与应用查询范围内峰值分别标明，不混用统计范围 |
| 温度 | 遍历所有设备报告的温度传感器，保存名称、位置、当前值、单位和健康状态 |
| 风扇 | RPM 独立；所有品牌统一一个“转速百分比（%）”指标 `fan.percent`，优先有效原生 PWM，其次有效普通百分比，不换算、不平均；同一风扇不重复统计，详见统一方案 |

每项数值包含 Value（可空）、Unit、ObservedAt、设备时间（若有）、Source 和 Availability。明确区分不支持、未安装、权限不足、读取失败和过期；合法零值与缺测不同，缺失不补 0。采样周期表示轮询间隔，不承诺设备传感器同频更新。

HPE 旧版文档的 Gen9/固件基线及风扇单位说明见[官方 iLO4 API](https://hewlettpackard.github.io/ilo-rest-api-docs/ilo4/)。本次 Gen8 真机也已返回 Redfish 主机资源，因此按实际固件和能力实现，不把旧文档的首发范围当成所有后续固件的限制，也不凭控制器名称承诺统一字段。Dell 按[本代 API 指南](https://dl.dell.com/topicspdf/idrac7-8-lifecycle-controller-v2.40.40.40_api-guide_en-us.pdf)及真机能力读取，不照搬新一代控制器的路径。

## 5. 电源操作

- 界面区分开机、优雅关机、强制关机、优雅重启与强制重启，只展示实际支持的动作；普通“重启”不能暗中映射强制动作。
- 目标是 ComputerSystem 的主机电源动作，禁止误调用 Manager.Reset 重启带外控制器。
- 服务端再次检查登录、权限、服务器状态、能力和动作；确认界面显示服务器与实际语义。
- 每次操作有稳定操作 ID/幂等键，同服务器串行；提交后超时不重发，优雅等待超时不自动升级成强制关机。
- 分别返回拒绝、已提交、已确认、结果未知；BMC 接受请求不等于服务器完成操作。只读查询用于核对，重启前后均为 On 不足以证明已完成重启。
- 写操作实现的自动测试只请求模拟服务。真实设备采集账号可读写不等于授权实际操作电源；开发配置默认禁止联调脚本发送真机电源写请求，交付时提供启用与人工验证方法。
- 保存操作审计，包括操作者、服务器、动作、提交/核对时间及安全结果；日志不保存密码或认证头。

拟新增独立 Compose 项目 `oob-management`，映射 `127.0.0.1:55432`，使用本项目命名卷。候选 PostgreSQL 17 + 兼容 TimescaleDB 2.31.x，具体 ARM64 镜像 tag/digest 在网络恢复后核验锁定；不使用浮动 latest，不写成已可拉取。

同一 PostgreSQL 实例下建立 `oob_management_dev` 与 `oob_management_test`，共用技术与迁移链，测试不污染开发服务器配置或采样。运行身份与结构迁移身份分离。

| 拟新增表 | 内容 |
| --- | --- |
| OOB_USER | 用户、密码哈希、状态 |
| OOB_USER_PREFERENCE | 账号外观与表格白名单设置 |
| OOB_SERVER | 服务器、控制器、地址、凭据密文和采样设置 |

时序样本使用 `(SeriesId, SampledAt)` 复合主键和对应 EF 映射；唯一约束包含时间分区列。历史接口按范围使用时间桶返回 min/max/avg、真实点数及缺口，不让浏览器一次拉取全部原始数据。[TimescaleDB 唯一索引要求](https://www.tigerdata.com/docs/build/performance-optimization/hypertables-and-unique-indexes)

首次建库、启用扩展和 EF 初始迁移使用明确初始化入口；应用正常启动不 Migrate/EnsureCreated。表、字段写中文注释。默认不启用自动删除原始历史的保留策略，聚合/压缩随实际规模再确认。

TimescaleDB 镜像、版本、架构和许可需分别核验，参见[官方镜像工程](https://github.com/timescale/timescaledb-docker)、[支持矩阵](https://www.tigerdata.com/docs/get-started/timescaledb-supported-platforms)及[许可](https://www.tigerdata.com/legal/licenses)。

## 7. 认证与私密配置

- 初始化用户名 admin，初始密码取用户指定值，只经本机私密配置传入、使用标准 PasswordHasher 哈希入库；幂等初始化不覆盖已有账号密码。
- 同源 Cookie 会话、退出失效、写请求防伪与服务端权限；前端不存管理员或 BMC 密码，不伪造登录成功。
- iDRAC8 在每轮操作内创建标准认证 Session、复用内存 token 并注销本轮所属会话，减少重复 Basic 认证开销；iLO4 保持已实测的 Basic 兼容读取。认证生命周期不属于主机电源或配置动作。GET 遇到会话失效最多刷新一次，设备电源写请求不自动重发。只读 Probe 默认严格 GET；显式 `--session-auth` 仅在受支持的驱动额外放行受限认证生命周期。
- BMC 密码后端加密存储；Data Protection 密钥与数据库分别持久化，私密目录限制本机账号读取，不写入共享仓库。生产密钥静态保护另按部署目标配置。[Microsoft 密钥存储说明](https://learn.microsoft.com/en-us/aspnet/core/security/data-protection/implementation/key-storage-providers?view=aspnetcore-10.0)
- 按用户后续确认的单设备证书策略，新增服务器默认勾选忽略 HTTPS 证书错误，取消后按系统证书链验证；填写指纹时始终优先固定该证书。策略只作用于当前设备，不修改系统信任库或其它客户端；请求仅允许已配置目标与确认的同源资源。
- 数据库账号、初始化参数和设备测试连接放忽略的本机配置中；新建私密配置与密钥仅在本次方案获授权后执行。现有其他项目的配置和代理不修改。

## 9. 实施顺序与验收

1. 确认本方案及数据库结构、私密配置初始化范围。
2. 搬入模板并调整必要运行配置，建立后端四层、认证、统一接口与新 OpenAPI 生成链；适配规则和真实验证入口。
3. 准备项目 Compose、私密配置、数据库/扩展、迁移与初始化；恢复镜像网络后验证真实数据库，不修改已有服务。
4. 实现两类驱动、服务器管理、静态库存、采集与时序落库，再完成总览、详情、实时与历史页面。
5. 实现电源动作及模拟测试；真实设备只做读取采样，电源动作由使用者人工验收。

自动验证覆盖构建/类型/静态检查、认证、权限、统一返回、驱动单位和能力映射、缺测与部分失败、调度不重叠、真实 PostgreSQL/TimescaleDB 迁移及样本/历史查询、幂等和写请求未知结果。浏览器检查登录/退出、账户与系统设置、异常页、语言、齿轮主题、控制台及关键失败请求。

测试使用隔离数据库与带标识夹具，只清理本次创建的数据；不删除文件或既有资源。代码/模拟、真实数据库、真实设备只读联调和人工电源验收分别记录，未执行不能标记通过。

## 10. 实施范围与边界

- 本方案覆盖 PC 独立 Umi 工程（保留模板原锁）与服务端四层工程。
- 开发/测试库、扩展、业务表与超表通过 EF 迁移建立；普通启动不自动建库或迁库。
- 私密配置、数据库凭据与加密密钥由部署者通过环境变量或私有目录提供，不进入仓库、示例、前端或日志。
- 本方案不包含删除既有文件/目录/卷、修改其他项目、全局安装、代理调整或任何真机电源操作；这些操作需按所在环境的流程单独确认。

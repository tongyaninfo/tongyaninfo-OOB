# ADR-0004 业务后端采用分层架构

- 日期：2026-10-19
- 状态：已接受，已按此实施

## 背景

早期后端规则曾按 `Controllers/<模块>`、`Services/<模块>`、`Services/<模块>/impl`、`Models/<模块>/Do|Dto|Vo` 组织（偏 Java 风格）；带外管理系统采用 Domain / Application / Infrastructure / Api 四层后，模块边界与依赖方向更清晰。业务代码建立前统一分层成本最低。

## 决定

业务后端与工作流后端保持一致的分层：

| 项目 | 内容 |
|---|---|
| `OobManagement.Domain` | 领域实体、枚举、领域规则，不依赖其他层 |
| `OobManagement.Application` | 应用服务接口、DTO、统一返回、分页与业务规则 |
| `OobManagement.Infrastructure` | EF Core / PostgreSQL、外部集成（ERP、MDM、工作流客户端）、服务实现 |
| `OobManagement.Api` | HTTP 宿主、Controller、鉴权、中间件、序列化、审计 |

各层内部按业务模块分目录。项目的具体命名在工程初始化时确定，ERP/SAP 集成可视规模独立为项目。

## 影响

原规则中关于 ApiResult、IdService、long 字符串、UTC、EF 迁移、PostgreSQL 建模、审计等约束不变，仍见 业务后端设计约束。

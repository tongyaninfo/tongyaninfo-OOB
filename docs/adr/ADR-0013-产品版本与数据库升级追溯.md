# ADR-0013：产品版本与数据库升级追溯

- 日期：2026-11-03。
- 决策状态：接受；以 1.0 建立源码基线与后续版本/升级规约。
- 实施状态：版本来源、迁移台账与仓库检查链已落实；目标环境升级不在本记录范围。
- 评审状态：已进行交叉代码检查；发布确认由维护方按流程执行。

## 背景与选择

PC 模板包号、桌面安装号、默认 .NET 版本和曾覆盖的镜像 `1.0` 标签不能共同唯一定位产品。系统已拥有 PostgreSQL 业务、OAuth 与桌面 SQLite 三条 EF 链，包含数据归并和权限回填；只记录最新迁移或重建初始库会丢失旧系统升级所需证据。

选择复用现有 EF 增量链，新增统一产品版本及静态可审阅台账；不新增业务版本表、自动迁库或竞争迁移器。仅靠手写 CHANGELOG 无法发现历史迁移改写；仅靠镜像标签无法说明 schema；重建初始迁移不适合已有数据，因此均不采用。

## 决定

1. 根 `VERSION` 为稳定三段产品版本的唯一来源，初始为 `1.0.0`。.NET 构建属性读取，PC 构建读取并注入产品信息，桌面 package/lock 作为安装工具必需镜像保持一致。模板和依赖版本独立保留。
2. 每个任务关联目标版本、数据库影响和验证入口；每个版本保存 Markdown 说明及新建后封存的 JSON 台账。台账含三链完整有序 MigrationId、历史迁移/Designer/SQL helper SHA-256、相对变更摘要和上一版本关联；无变化显式登记。
3. 已封存迁移与历史台账不覆盖，修正追加新版本。可变 EF ModelSnapshot 正常演进，不冻结为所有后续版本必须相等的文件。SHA-256 记录不复制源码，不能充当完整源码或数据库备份。
4. `scripts/releases.mjs record` 只新建待补摘要的正式记录，拒绝覆盖；`check` 只读核对产品一致性与迁移追溯，并进入现有验证入口。静态校验不连接数据库、不创建/迁移结构、不读取秘密。
5. 升级继续显式授权，默认短维护停写、单执行者、先备份后迁移。服务端业务链先于 OAuth，桌面走独立 SQLite；schema/SearchPath、Provider、引擎/扩展版本按实际目标核对。
6. 程序降级须先证明数据兼容，不默认执行 `Down`；不可逆变换使用配套快照恢复。密钥/配置和必要运行文件与数据库一同考虑。迁移、制品发布与环境验收分别留证。
7. 新制品按完整产品版本和不可变内容摘要定位，已交付标签不覆盖。既有 `1.0` 覆盖记录保留，不将历史标签补称为本次新 `1.0.0` 发布。

## 影响与恢复边界

开发者须在编码前确定目标版本，完成迁移生成后建立正式台账并补中文摘要；共享模型维护两个 Provider，OAuth 保持独立所有权。启动、查询和健康检查不隐式升级，服务端现有 `--initialize` 的 Bootstrap 行为不改变。

本决定新增源码追溯约束，不新增数据库结构。未来版本兼容/恢复验证必须在获准真实 Provider 上完成；本次非数据库验证不证明任何环境升级完成，也不保证零停机。完整操作规约见[版本与数据库升级](../releases/README.md)。

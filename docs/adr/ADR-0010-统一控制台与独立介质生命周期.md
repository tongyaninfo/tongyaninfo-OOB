# ADR-0010：统一控制台与独立介质生命周期

- 决策状态：接受；统一控制台与独立介质生命周期按本方案实施。
- 实施状态：代码已实施并通过自动化自检；界面与设备能力以实际固件、浏览器环境为准。
- 评审状态：已进行交叉代码检查；人工评审与业务验收按各部署环境单独执行。

## 背景与备选

iLO4 与 iDRAC8 的 HTML5 控制台不是同一种 RFB/VNC 协议。直接嵌入管理整站会暴露原生电源/配置入口与跨来源认证问题；统一使用 noVNC 又不能覆盖 iLO4，Dell VNC 还需要独立配置和许可。重写完整视频解码器成本高，也不能由 Redfish 能力推导协议兼容。

本地 ISO 直接映射依赖浏览器按需读取，URL/平台镜像库则由 BMC 独立拉取，不能把关闭画面当作拔出介质。挂载超时后重发可能覆盖正在使用的介质，必须先记录意图并核对原状态。

## 决定

1. PC 使用自有多标签、工具栏、完整屏幕键盘、全屏和介质抽屉。会话与鉴权由现有后端承接，视频不进入遥测 SignalR。
2. 厂商 HTML5 解码器仅在运行时从已登记设备读取，按已审查原样摘要逐项校验，不提交或重新分发厂商 JS。最小画布外壳通过随机挑战值绑定父窗口、Origin 和会话，CSP 限制脚本、Worker 与 WebSocket。
3. 浏览器不持有设备真实认证密钥。后端替换固定认证帧并逐类限制客户端协议，拒绝电源、启动设备、抢占和未知管理命令。输入门控与按键释放由服务端再次执行。
4. 本地映射首期只提供非空只读 ISO，沿用已确认的原生 FileReader/介质协议。URL/镜像库通过设备声明的标准或 HP OEM 介质动作对接；启动项、重启与挂载分开。
5. 可选镜像库及介质意图使用仓库外单实例文件存储。独占租约防止多进程共写，追加日志先持久化请求再发送；来源 URL 用既有 Data Protection 保护，供给凭据只存摘要。不改数据库结构，未来迁库须单独确认。
6. 会话及意图绑定登记服务器与规范化控制器地址身份。目标变化后不复用旧会话、不将旧挂载认领到新设备。未知结果按原请求查询，确实未执行时仅由原操作人填写核对依据结束意图，不代发动作。
7. 原生介质流量是会话总量的子集，平台镜像 HTTP 读取另报；不重复相加，不声称网卡线速、外部 URL 流量或安装完成率。

## 兼容、恢复与限制

资源变化或未知固件须先审查，不能取消摘要校验继续执行。平台镜像库发布地址不影响本地 ISO 或设备已支持的 URL 来源；物理 USB 穿透、可写镜像及其它类型不由 ISO 能力推定。

进程重启关闭画面，不自动重连或回放输入。本地 ISO 受浏览器/会话关闭影响；URL/镜像库维持独立生命周期。恢复日志须配套原 Data Protection 密钥；损坏、目标身份缺失或密钥不匹配时不认领介质、不重发。已挂载镜像不自动删除；卸载确认或后续查询发现介质已被弹出/更换时撤销对应供给授权。

真实输入、挂载和客户机识别需要人工验收。模拟协议、真实 Testing 数据库、构建和浏览器替身回归分别证明各自边界，不代替真机业务验收。

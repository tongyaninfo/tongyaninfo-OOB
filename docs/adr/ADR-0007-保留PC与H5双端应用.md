# ADR-0007 保留 PC 与 H5 双端应用

- 日期：2026-10-20
- 状态：已实施

## 背景

带外管理前端最初按 PC（桌面浏览器）与 H5（移动浏览器）两个独立应用规划。曾评估将两端合并为单一响应式应用以减少重复页面，但移动端与桌面端的交互、组件与验收标准差异较大，合并会增加复杂度并削弱各自体验。

## 备选方案

| 方案 | 评价 |
| --- | --- |
| 合并为单一响应式应用 | 维护成本看似降低，但页面、组件与验收标准难以兼顾，未采用 |
| 恢复 PC/H5 双端独立目录 | 采用；两端各自维护入口、依赖与规则，共享逻辑通过明确边界复用 |
| 同时保留合并与拆分 | 三端并行、职责不清，不采用 |

## 决定

- 保留 `frontend/PC` 与 `frontend/H5` 两个独立应用目录，各自拥有 README 与工程配置。
- PC 采用 Umi Max + Ant Design 6 模板工程与独立锁文件，作为当前正式交付端。
- H5 作为后续移动端方向保留目录与说明，未建立应用包前不承诺可用能力。

## 影响

- 新增业务功能默认先落在 PC 端；H5 需要单独评估技术选型与交互。
- 两端不共享 UI 组件；跨端共享的类型与合同通过后端接口合同与生成物复用，不直接互相导入源码。
- 后续若重新评估合并，应按新的 ADR 重新评审，不在本 ADR 上改写结论。

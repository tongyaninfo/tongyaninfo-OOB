# 架构决策记录（ADR）

记录影响架构、跨模块合同或实现方式的重要决定。一条决定一个文件，编号递增，文件名为 `ADR-<四位编号>-<主题>.md`。

## 何时写 ADR

- 引入新的公共依赖、框架或中间件。
- 新增或调整跨端、跨服务合同，包括 API、事件和嵌入协议。
- 调整持久化、身份权限、状态协议，或实施不兼容升级。
- 改变目录结构或分层方式。

## 约定

- 新决定使用下一个编号，不覆盖历史记录；被取代的决策在正文标注状态与替代关系。
- 决策记录说明背景、备选方案、决定与后果；实施状态与评审状态分别标注，不把「已实施」等同于「已验收」。
- 常规实现细节写在模块 README 或代码注释中，不单独建 ADR。

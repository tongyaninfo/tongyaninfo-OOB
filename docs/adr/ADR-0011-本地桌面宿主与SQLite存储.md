# ADR-0011 本地桌面宿主与 SQLite 存储

- 决策状态：接受；桌面使用 SQLite 本地方案。
- 实施状态：已实施；实际平台与验证边界见桌面说明，不代表正式发布。
- 评审状态：AI 自检不代替人工验收或非作者评审。

## 背景与决定

用户要求安装后无需单独部署服务器，项目置于 `desktop`，使用 .NET + Electron，桌面仅 SQLite，同时保留现有服务端 PostgreSQL 实现。

采用 Electron 主进程管理本地 .NET 10 自包含宿主；宿主同时提供既有 Umi PC 产物、API和WebSocket，使用动态 loopback HTTP 同源，保留 Cookie、CSRF和控制台来源校验。启动秘密仅父子管道传递并用于本次 HttpOnly 门禁，不进入 URL、持久化配置或日志；页面不取得 Node 权限。

复用现有 Controller、应用服务、领域实体和带外驱动。数据库差异通过窄存储策略与 SQLite DbContext 子类处理；桌面拥有独立迁移集，保留既有 PostgreSQL/Timescale 迁移。SQLite 使用UTC微秒INTEGER、JSON TEXT、确定性账号规范化、短写事务和数据库内历史聚合。与整体复制四层工程相比，此方式保留业务单一来源；与内置 PostgreSQL 相比，符合用户最终明确的 SQLite 单库范围。

## 生命周期与副作用

首次或升级由用户显式确认，普通启动不建库迁库；采集和故障补入等待结构就绪。桌面数据目录独占，有托盘时关窗保留页面与后台，显式退出正常停服务。崩溃/休眠不补造历史、不重发真机操作。

镜像库内容供给采用默认关闭的独立 LAN 端口和明确 BMC IP 白名单，仅开放原授权镜像 GET/HEAD；业务 API 仍为 loopback。此端点与本地 ISO 直接映射的生命周期分别处理。

## 兼容与恢复

服务端默认仍为 Npgsql、原时序超表与原迁移链；API合同、长ID字符串、时间和权限语义继续复用。SQLite 迁移和时间桶通过真实文件数据库验证，原 PostgreSQL 使用现有 Testing 库回归，不自动修改现有库结构。

备份使用 SQLite 在线快照并包含配置密钥及独立介质状态；恢复写入新目录，拒绝覆盖与路径越界，保留失败现场。升级先备份；不以替换二进制推导数据结构可回退。

# ADR-0012：MCP 服务授权与离线合同

- 日期：2026-11-02。
- 决策状态：接受；MCP 服务按本方案实现。
- 实施状态：本地实现与自检完成；生产配置、目标客户端接入与实际部署按部署环境单独验证。
- 评审状态：已进行交叉代码检查；人工业务验收由使用方执行。

## 背景

系统需要在“系统管理”下管理 MCP 服务开关、调用方白名单及调用日志，并提供本系统已有能力。现有 PC 使用 Cookie/CSRF，设备操作有四项独立权限，但普通登录查询没有 MCP 所需的逐设备范围。远程调用不能复用 Cookie 或仅按调用方上报名称决定身份，也不能把 MCP 工具目录公开为无鉴权的设备接口。

用户同时要求移除 Swagger/OpenAPI 相关模块和服务。旧离线合同依赖运行宿主中的 Swashbuckle，PC 的 DTO 又直接引用生成类型；直接删包或产物会破坏前端与所有非 docs 验证。因此须先替代完整 REST 合同链，不能仅去掉 UI 或把 MCP Schema 当成全部 HTTP 合同。

## 备选

| 选项 | 取舍 |
| --- | --- |
| 静态 API Key 或浏览器 Cookie | 接入简单，但不能满足本次标准 OAuth/PKCE、用户同意和令牌撤销范围；不采用 |
| 将现有 REST 全部自动暴露为工具 | 不能可靠区分设备写入、主动采集、凭据或副作用；不采用 |
| 仅关闭 Swagger UI、保留生成服务与 OpenAPI 链 | 对消费者改动小，但未完成完整退役范围；不采用 |
| 移除合同、手写 TypeScript DTO | 失去唯一来源与漂移门禁；不采用 |
| 独立协议适配、明确工具与范围，单独替代离线合同 | 改动较多，但保留现有业务分层和可审阅边界；采用 |

## 决定

1. 服务端在同一 HTTPS 宿主提供 `/mcp`，采用官方 `ModelContextProtocol.AspNetCore 2.3.0`。主协议目标为 `2026-07-28`，兼容目标为 `2025-11-25`，对应发现、初始化及传输由 SDK 实现。协议目标不等于所有客户端已经兼容，实际矩阵单独登记。
2. 提供十个查询工具，只读已保存的设备、库存、监测、历史、异常、电源记录和结构化运行统计。电源/UID写入、控制台输入、虚拟介质、主动采样/刷新、邮件发送、用户修改和凭据导入导出不开放。
3. 采用 OAuth 授权码与 PKCE，客户端由管理员预注册、精确登记 redirect URI，绑定系统用户。OpenIddict 处理授权、令牌与撤销，锁定 `7.5.0` 以兼容现有 EF Core；本次不采用会引入 EF 依赖冲突的 `7.7.2`，不顺带升级存量 EF/Npgsql。
4. 每次调用交集原同意快照与当前用户、AuthVersion、客户端状态、全局及客户端工具、服务器和网络规则；查询前过滤 SQL，返回前复核。系统管理员身份不绕过独立业务权限。Origin 存在时额外精确验证；转发头只信任配置的代理。
5. 服务与新调用方默认关闭，工具/网络空列表表示不授权；启停为独立动作，保存不启用。版本冲突返回真实 `409`。全局停用/策略变化与客户端停用/撤销会取消本进程活跃查询；最终授权复核继续防止竞态。
6. MCP 调用和 OAuth 响应独立审计，JSON-RPC 的 HTTP200 错误也标记失败。审计写 DB 或受保护缓冲均失败时拒绝继续；拒绝日志有采样上限，正常成功调用完整记录。秘密和任意请求/结果正文不进入审计。
7. 七张 MCP 业务表沿用 OobDbContext 的 PostgreSQL 与 SQLite 增量迁移；OAuth 组件存储采用独立 McpOAuthDbContext、独立历史表与版本链。普通启动不迁库；迁移生成、执行环境和部署按本次明确授权分别处理。
8. 桌面强制关闭外部 MCP，保留 Gate 和独立 LAN 介质边界；共享业务实体与 PC 合同仍同步兼容。后续本地 MCP 监听另作设计。
9. 移除 Swagger/OpenAPI 运行服务、UI、模板插件、旧产物和旧生成依赖。新开发工具独立创建 MVC 元数据容器，通过 ApiExplorer/EndpointDataSource 与 JsonTypeInfo/JsonSchemaExporter 生成 `routes.json`、`schemas.json`；不调用业务宿主，不加载私密配置、数据库、采集或发信。
10. 父前端锁定 `json-schema-to-typescript 16.0.0`，同源生成 PC 的 `generated.ts`，保留 `components.schemas` 类型出口及现有 schema 键。后续逐字校验三份制品，同时验证长 ID、可空、必填、枚举、递归和泛型分页语义。

## 影响和兼容

新增 PC `/system/mcp`、`/system/mcp/logs`；管理 API 继续使用 Cookie/CSRF 和 ApiResult。MCP、OAuth、SignalR、二进制和健康响应保持原生格式，全局错误处理中间件不得覆盖协议。旧 Swagger/OpenAPI 路径真实返回 404，不回退为前端 HTML。

普通浏览器查询维持现有范围；MCP 专门的受控查询不能直接透传包含管理账号、地址或证书策略的完整 ServerDto。异常工具要求管理员及显式全部设备授权；电源记录要求当前 PowerOperations，运行统计要求管理员。工具 Schema 与 REST 合同分别维护。

离线工具从正式 Controller 注册提取方法，包含 IgnoreApi 的资源和流入口。健康、SignalR、MCP/OAuth 地址共用正式路由常量；动态 ServiceResult 分支、流式响应头和业务副作用继续依靠接口说明与行为测试，不能宣称反射已证明全部运行状态。

## 恢复和验证边界

发布时保持 MCP 关闭，按目标环境备份并显式迁移后再配置和启用。失败时优先关闭 MCP，保留调用审计与新表；回退程序前检查增量结构兼容性，不自动降库、删除表或覆盖密钥。OAuth 恢复需同时核对数据库、签名/加密材料及撤销状态。

本 ADR 记录已确认开发选择和代码边界，不宣称生产已部署。必需检查、隔离真实 Provider、官方 SDK 两版本、真实目标客户端和浏览器分别报告；真机电源或其他设备写入不进入自动验证。接入步骤、配置与限制见[MCP说明](../api/mcp/README.md)，离线合同见[工具说明](../../backend/tools/OobContracts/README.md)。

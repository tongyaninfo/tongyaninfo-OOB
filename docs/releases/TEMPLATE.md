# 产品版本说明模板

复制为真实版本号的 Markdown；所有占位信息须按实际情况填写，未验证项明确写“未运行”，数据库没有变化也不能省略。

## 版本信息

| 字段 | 内容 |
| --- | --- |
| 产品版本 / 日期 | `MAJOR.MINOR.PATCH` / `YYYY-MM-DD` |
| 状态 | 开发中 / 源码基线；制品发布与各环境升级另列证据 |
| 来源版本 | 支持的明确版本；不支持的来源及桥接步骤 |
| 关联 Issue / PR | 真实链接，或“未关联” |
| 机器台账 | 本版本 JSON 相对链接 |

## 功能与兼容性

填写用户可见变化、修复、公开 API/配置/协议的兼容性。列受影响的服务端、PC、桌面与必要依赖；版本无功能变化时也写明。

## 数据库变更

| 链 | 来源完整基线 → 目标末端 | 本版新增/变换 | 风险与恢复 |
| --- | --- | --- | --- |
| PostgreSQL / OobDbContext | 真实 MigrationId | 无，或表列/索引/约束/注释/数据变换及脚本 | 前置条件、锁与数据量、可逆性 |
| PostgreSQL / McpOAuthDbContext | 真实 MigrationId | 无，或组件变化 | 单独核对历史与组件材料 |
| SQLite / SqliteOobDbContext | 真实 MigrationId | 无，或 Provider 对应变换 | SQLite 专属限制 |

完整有序迁移及历史源码摘要以本版 JSON 为准。写明实际 schema/SearchPath 核对方法、引擎/扩展变化（无也写明）、数据守恒和默认值/权限回填规则。

## 升级与恢复

填写支持的起点、预估/待测维护时长、停写者、单执行者、备份范围/恢复点、纯迁移步骤及目标核对；链接共用[升级规约](README.md)，只补本版差异。明确 `--initialize`/种子副作用、不可逆步骤和两条服务端链的部分成功处理。

填写旧程序兼容结论及依据；不能证明时恢复配套数据库、密钥/配置与制品，不默认执行 `Down`。记录恢复演练状态、快照后数据处理及已知阻断。

## 验证与发布边界

逐项记录通过、失败、未运行、跳过及真实证据：版本/摘要校验、构建/测试、空库安装、旧版有数据升级、重复执行、失败恢复、真实 Provider、浏览器/平台/设备验收。静态检查不等于实际升级。

制品发布另附不可变摘要、架构说明；环境应用另附前后迁移/schema、备份与人工验收。没有执行的打包、部署、评审或签字不能填写为完成。
